1. INTRODUCTION                                                *vimf90-intro*

|vimf90| turns Vim / Neovim into a modern, responsive IDE for Fortran.

Key Features:
  * Automatic `fortls` project configuration: generates a correct `.fortls` from
    your |fpm| layout so the language server indexes your sources and your
    dependencies, and never the `build/` tree. See |vimf90-lsp|.
  * First-class Fortran Package Manager (|fpm|) integration (`build`, `run`, `test`, `new`).
  * Interactive LFortran REPL session runner and ephemeral scientific scratchpad.
  * Intelligent multi-file project management: root detection (`fpm`, `CMake`, `Makefile`),
    automatic module search path (`-I`) resolution, and project-wide Universal Ctags.
  * Native Fortran text objects (`af`/`if`, `am`/`im`, `at`/`it`, `ad`/`id`, `ab`/`ib`)
    and structural subprogram motions (`]m`, `[m`, `]M`, `[M`).
  * Automatic FORD & Doxygen docstring generator (`:FortranDoc`, `<leader>dc`)
    with argument type and intent deduction.
  * Scientific HPC presets: Debug, Release, Fast, and Sanitize profiles, with
    OpenMP multithreading and MPI wrapper toggles.
  * Non-blocking asynchronous compilation and linking using Vim 8/9 jobs and
    Neovim async jobs with multi-compiler QuickFix parsing (`gfortran`, `ifx`, `ifort`, `nvfortran`, `flang`).
  * Buffer-local isolation with complete |b:undo_ftplugin| support.

  * Snippets: honza/vim-snippets or friendly-snippets with LuaSnip / UltiSnips
  * Symbol Outline: majutsushi/tagbar or stevearc/aerial.nvim

3. CONFIGURATION OPTIONS                                     *vimf90-options*

*g:fortran_leader*
    Leader key used for default vimf90 mappings.
    Default: |mapleader| or "\"

*g:fortran_compiler*
    Fortran compiler executable.
    Default: "gfortran" (supports "ifx", "ifort", "nvfortran", "flang", etc.)

*g:fortran_profile*
    Active compilation profile: "debug", "release", "fast", or "sanitize".
    Default: "debug"

*g:fortran_async*
    Enable asynchronous non-blocking compilation for Vim 8+ and Neovim.
    Default: 1

*g:fortran_repl_command*
    Executable command to start the interactive Fortran REPL.
    Default: "lfortran"

*g:fortran_repl_split*
    Window split command for opening the REPL terminal.
    Default: "botright 15split"

*g:fortran_scratch_split*
    Window split command for opening the scientific scratchpad.
    Default: "botright vsplit"

*g:fortran_format_on_save*
    Automatically format buffer with `fprettify` on save.
    Default: 0

*g:fortran_doc_style*
    Docstring template style: "ford" or "doxygen".
    Default: "ford"

*g:fortran_run_terminal*
    Run executables and debuggers in a bottom terminal split instead of external shell.
    Default: 0

4. COMMANDS                                                 *vimf90-commands*

All commands are buffer-local and available in Fortran buffers:

*:FortranReplToggle*
    Toggles the interactive LFortran REPL terminal split.

*:FortranReplOpen* [cmd]
    Opens or focuses the interactive Fortran REPL session.

*:FortranReplSend*
    Sends current line (or visual selection) to the active REPL.

*:FortranReplSendSubprogram*
    Sends the enclosing subroutine, function, or module to the REPL.

*:FortranReplSendBuffer*
    Sends the entire active buffer to the REPL.

*:FortranReplRestart*
    Restarts the active REPL terminal session.

*:FortranScratch* [program|matrix|openmp|module|test]
    Opens a temporary scientific scratchpad pre-populated with a clean modern template.

*:FortranScratchRun*
    Instantly compiles and executes the active scratchpad buffer, displaying output.

*:FortranCompile*
    Compiles current buffer to an object file (`.o`), auto-resolving project include paths.

*:FortranExe*
    Compiles and links current buffer to an executable.

*:FortranRun*
    Builds and runs the current buffer's executable.

*:FortranArgs*
    Prompts for command-line arguments to pass when executing the binary.

*:FortranDebug*
    Builds with debug flags (`-g`) and starts the debugger (`gdb` or `lldb`).

*:FortranDoc* [ford|doxygen]
    Generates a FORD or Doxygen documentation block above the current subprogram,
    module, derived type, or interface.

*:FordBuild*
    Builds project FORD documentation asynchronously from the project root.

*:FordPreview*
    Builds and opens project FORD documentation index (`doc/html/index.html`) in
    the default web browser.

*:FortranProfile* [debug|release|fast|sanitize]
    Sets the active compilation profile (compiler flags).

*:FortranCompiler* [gfortran|ifx|ifort|nvfortran|flang]
    Sets the active compiler backend.

*:FortranOpenMP* [on|off|toggle]
    Toggles OpenMP multithreading compilation flags (`-fopenmp` / `-qopenmp`).

*:FortranMPI* [on|off|toggle]
    Toggles MPI compiler wrapper (`mpifort`, `mpiifx`, `mpiifort`, `mpif90`).

*:FortranFpm* [subcommand]
    Runs an `fpm` command (with tab-completion for `build`, `run`, `test`, `new`, `add`, `clean`, etc.).

*:FortranFpmBuild* [args]
    Runs `fpm build` asynchronously from the project root.

*:FortranFpmRun* [args]
    Runs `fpm run` from the project root.

*:FortranFpmTest* [args]
    Runs `fpm test` from the project root (supports target completion).

*:FortranFpmTestCurrent*
    Runs only the unit test in the active buffer under the cursor.

*:FortranFpmAdd* <dependency>
    Adds a standard library dependency (`stdlib`, `test-drive`, `lapack`, `toml-f`) to `fpm.toml`.

*:FortranFpmNew* [name]
    Initializes a new Fortran Package Manager project.

*:FortranProjectBuild* [args]
    Automatically builds the project using detected build system (`fpm`, `cmake`, `make`).

*:FortranProjectRoot*
    Displays the detected project root directory.

*:FortranFortlsConfig*
    Generates or synchronizes `.fortls` LSP configuration derived directly from
    `fpm.toml`, source directories, and `build/dependencies/` without scanning
    hash-churned compiler artifact directories.

*:FortranTags*
    Generates / updates Universal Ctags across the entire Fortran project.

*:FortranFindModule* [name]
    Searches the project for the file defining `module <name>` and opens it.

*:FortranFormat*
    Formats current buffer using `fprettify`.

*:FortranMake*
    Executes `:make` (historical fallback for Makefile repositories).

*:FortranMakeArgs*
    Prompts for make properties/targets.

6. INTERACTIVE LFORTRAN REPL & SCRATCHPAD                      *vimf90-repl*

|vimf90| brings Julia / Python-style interactive scientific prototyping to Fortran:

1. Interactive LFortran REPL:
   * Launch or toggle the interactive REPL split with `<leader>rt` or `:FortranReplToggle`.
   * Send the current line with `<leader>rs` or visually select multiple lines and press `<leader>rs`.
   * Send an entire subroutine or module with `<leader>rm` (`:FortranReplSendSubprogram`).
   * Send the whole active file with `<leader>rb` (`:FortranReplSendBuffer`).
   * Automatically works with Neovim (`termopen`/`chansend`) and Vim 8+ (`term_start`/`term_sendkeys`).

2. Instant Scientific Scratchpad:
   * Open an ephemeral, disposable scratchpad with `<leader>so` or `:FortranScratch [template]`.
   * Templates available: `program`, `matrix`, `openmp`, `module`, `test`.
   * Compile and run the scratchpad instantly with `<leader>sr` (`:FortranScratchRun`). Output is
     displayed side-by-side in a dedicated scratch output window.

7. FORTRAN PACKAGE MANAGER (FPM) & LSP SYNC                     *vimf90-fpm*

|vimf90| provides first-class support for modern `fpm` (https://fpm.fortran-lang.org/).

When working inside an `fpm` repository (any folder containing `fpm.toml`),
|vimf90| automatically detects the project root and synchronizes active profiles.

  * `<leader>fb` or `:FortranFpmBuild`: Compiles the whole project asynchronously and
    automatically regenerates `.fortls` if dependencies or module layouts changed.
  * `<leader>fr` or `:FortranFpmRun`: Runs the project's executable application.
  * `<leader>ft` or `:FortranFpmTest`: Runs all unit tests.
  * `<leader>tc` or `:FortranFpmTestCurrent`: Runs only the test in the active buffer.
  * `:FortranFpmAdd <dep>`: Adds standard dependencies (`stdlib`, `test-drive`, `lapack`).
  * `:FortranFpmNew <name>`: Scaffolds a new standard Fortran package and initializes `.fortls`.
  * `:FortranFortlsConfig`: Manually generates or updates the `.fortls` LSP configuration.

8. LARGE MULTI-FILE PROJECTS & DELEGATION HOOKS             *vimf90-projects*

In 2026, Fortran projects often span hundreds of files across nested folders
with inter-module dependencies.

|vimf90| handles large projects through:
  1. Automatic Root Detection: Detects `fpm.toml`, `CMakeLists.txt`, `Makefile`,
     or `.git` up the directory tree.
  2. Authoritative Module & Include Path Discovery: Automatically extracts exact
     `-I` and `-J` module paths directly from `build/compile_commands.json` (falling
     back to heuristic scanning for pre-built states).
  3. External Root Provider Hooks:
     * `b:fortran_project_root` / `g:fortran_project_root`: Override root path directly.
     * `g:Fortran_root_provider`: Funcref returning root path (e.g. from `project.nvim` or `vim-rooter`).
  4. External Build Runner Delegation:
     * `g:Fortran_build_provider`: Funcref called before internal runner (e.g. for `vim-dispatch` or `asyncrun.vim`).
  5. Universal Ctags: Run `<leader>tg` or `:FortranTags` to generate tags across all
     modules, subroutines, types, and interfaces in the repository.
  6. Module Navigation: Run `<leader>fm` or `:FortranFindModule <name>` to instantly
     jump to the file defining a module.

8. TEXT OBJECTS & MOTIONS                                   *vimf90-textobj*

|vimf90| includes native Fortran text objects and motions:

  * `vaf`: Select entire subprogram (subroutine or function).
  * `vif`: Select body inside subprogram (excluding header and `end`).
  * `vam` / `vim`: Select around / inside module or program.
  * `vat` / `vit`: Select around / inside derived type definition.
  * `vad` / `vid`: Select around / inside `do` loop.
  * `]m` / `[m`: Jump to next / previous subprogram header.
  * `]M` / `[M`: Jump to next / previous `end subroutine` / `end function`.

10. FORD & DOXYGEN DOCSTRING GENERATOR                           *vimf90-doc*

Running `<leader>dc` or `:FortranDoc` above or inside any subroutine, function,
module, derived type, or interface automatically parses the parameter list,
inspects declared types, `intent(in/out/inout)`, and `optional` attributes,
and generates a formatted documentation header.

Run `:FordBuild` (`<leader>db`) to build project-wide FORD documentation
asynchronously, or `:FordPreview` (`<leader>dp`) to open it in your browser.

11. SUPERCOMPUTING, ACCELERATORS & HPC                          *vimf90-hpc*

|vimf90| provides first-class support for modern parallel standards and supercomputing:

1. Build Profiles (with Native ISO Coarray Fortran):
   * `:FortranProfile debug`   -> `-g -O0 -Wall -Wextra -fcheck=all -fbacktrace -fcoarray=single`
   * `:FortranProfile release` -> `-O3 -march=native -funroll-loops -fcoarray=single`
   * `:FortranProfile fast`    -> `-O3 -ffast-math -march=native -fcoarray=single`
   * `:FortranProfile sanitize`-> `-g -O1 -fsanitize=address,undefined -fcoarray=single`
   ISO Fortran Coarrays (`[*]`, `sync all`, `this_image()`) compile natively out-of-the-box.

2. OpenMP & MPI:
   * `:FortranOpenMP` (`<leader>po`): Toggles OpenMP multithreading flags.
   * `:FortranMPI` (`<leader>pm`): Toggles MPI compiler wrapper (`mpifort` / `mpiifx`).
   * `:FortranMPIRun [ranks]` (`<leader>pr`): Launches multi-rank MPI cluster job (`mpirun -n <ranks>`).

3. GPU Offloading (OpenACC & OpenMP Target Offload):
   * `:FortranGPU [openmp|openacc|off]` (`<leader>pg`): Toggles GPU acceleration flags
     for NVIDIA (`-acc`/`-mp=gpu`), GCC (`-fopenacc`/`-fopenmp -foffload`), and Intel (`-fopenmp-targets=spir64`).

Statusline helper:
Add `profiles#status()` to your statusline or lualine to display:
`[gfortran:Debug:OMP:MPI:GPU]`.

12. SCIENTIFIC DEBUGGING & MATRIX INSPECTOR                    *vimf90-dap*

Scientific debugging in computational physics often requires inspecting large
multi-dimensional arrays and matrix states:

1. Multi-Dimensional Array Inspector:
   * Run `<leader>da` or `:FortranInspectArray <var> [rows] [cols]` to open the
     dedicated Fortran Matrix Inspector window.
   * Displays formatted 2D grids with column-major ordering, row/column indices,
     and values queried live from GDB / DAP / Termdebug.

2. Breakpoints & DAP Integration:
   * Run `<leader>dt` or `:FortranBreakpointToggle` to set/clear breakpoints on the current line.
   * Run `:FortranDebug` (`<leader>cd`) or `:FortranTermdebug` to start interactive debugging.
   * Automatically configures `nvim-dap` for Neovim users with `gdb` and `codelldb` adapters.

16. LANGUAGE SERVER PROTOCOL (LSP)                              *vimf90-lsp*

                                                        *vimf90-fortls-config*
Nothing in the Vim ecosystem understands |fpm| projects. `fortls` has no fpm
awareness at all: its default `source_dirs` is `./**`, so on an fpm project it
recurses into `build/` and indexes a copy of your whole source tree for every
`build/<compiler>_<hash>/` directory fpm has ever produced. One project, six
profiles, six duplicate definitions of every module. `nvim-lspconfig` does not
list `fpm.toml` as a root marker either.

|vimf90| closes that gap by generating the manifest for you: >

    {
      "_generated_by": "vimf90",
      "source_dirs": ["app", "src", "src/utils", "test",
                      "build/dependencies/mydep/src"],
      "excl_paths": ["build", ".git"]
    }
<
Two details make this worth automating rather than writing by hand:

  * `fortls` does NOT recurse into explicitly configured `source_dirs`. A
    nested `src/utils` is invisible unless it is named, so every directory
    holding Fortran sources has to be enumerated, and re-enumerated whenever
    the layout changes.
  * `excl_paths` is exact string matching, not globbing. The `"build/**"` you
    would naturally reach for matches no directory at all and silently changes
    nothing, leaving the full recursive scan in place.

Dependency sources live under `build/`, which is excluded, so they are listed
explicitly; without that, every module coming from a dependency loses
completion and go-to-definition. `include_dirs` is deliberately left out: it
resolves preprocessor `#include` directives only. `fortls` never reads `.mod`
files, and module symbols come exclusively from parsed source.

Because no `build/<compiler>_<hash>` path is ever written into the manifest,
fpm's hash churn stops mattering: a new hash directory simply never enters the
index, and there is nothing to track. Regeneration is driven by source
directories changing, not by builds.

Regeneration happens on `:FortranFpmBuild`, on writing `fpm.toml`, on
`:FortranFpmNew`, and on demand via `:FortranFortlsConfig`. The file is
rewritten only when its contents would actually differ.

A hand-written `.fortls` is never touched: if the file lacks the
`_generated_by` marker, or cannot be parsed, |vimf90| leaves it alone. Set
`g:fortran_fortls_autoconfig` to 0 to disable automatic generation entirely;
`:FortranFortlsConfig` still works on demand.

Point your LSP client at the project with `fpm.toml` FIRST in the root
patterns: it is present before the first build, whereas `.fortls` only appears
once |vimf90| has written it. Rooting the server correctly matters as much as
scoping it, since `nvim-lspconfig`'s defaults for `fortls` are `.fortls` and
`.git`, and with neither nearby the server can root somewhere very large.

For coc.nvim, add the following configuration in your `coc-settings.json` or `.vimrc`: >
    let g:coc_user_config = {
          \   'languageserver': {
          \     'fortran': {
          \       'command': 'fortls',
          \       'args': ['--lowercase_intrinsics'],
          \       'filetypes': ['fortran'],
          \       'rootPatterns': ['fpm.toml', '.fortls', '.git/']
          \     }
          \   }
          \ }
<

18. TESTING                                                  *vimf90-testing*

The test suite is plain Vimscript built on Vim's own `assert_*` family, with no
external dependencies: >

    sh test/run.sh                       " everything
    sh test/run.sh textobj project       " selected files
    VF90_TEST=Test_name sh test/run.sh   " a single test
    VF90_VIM=nvim sh test/run.sh         " against Neovim
<
It exits non-zero on failure, so it drops straight into CI. Tests needing
`gfortran`, `fpm`, `fortls` or `luac` skip themselves when the tool is absent
rather than failing. The suite is green on both Vim 9.2 and Neovim 0.12.

The editor variable is `VF90_VIM`, not `VIM`, on purpose: $VIM is Vim's own
variable for locating $VIMRUNTIME. Exporting VIM=nvim sets $VIMRUNTIME to
"nvim", which breaks filetype detection and every other runtime file with it,
silently -- the editor still starts and still runs the tests. `test/run.sh`
therefore ignores a $VIM that is not a directory, since it cannot be a runtime
root and can only do harm.

`test/test_plugin.vim` guards the failure mode where code is never reachable at
all: an autoload file shadowing another plugin, an autocommand registered where
it cannot fire, embedded Lua that never parses, `\b` used as a word boundary
(Vim reads it as a backspace character, not a boundary), or a Funcref assigned
to a lowercase name (|E704|).
